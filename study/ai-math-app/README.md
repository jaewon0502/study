# Ai_Math_App(mathmvp)을 만들면서 배운 것들

- 프로젝트: iPad용 AI 수학 튜터. 학생 풀이에서 첫 불확실 단계를 찾고, 정답을 성급하게 공개하지 않으면서 다음 한 줄을 점진적으로 돕는다.
- 기간/규모: 2026-06-26 ~ 07-26, 커밋 147개, PR 36개+, 2인 협업 + AI 에이전트(Claude/Codex) 병행.
- 근거 문서: 저장소의 `docs/DECISIONS.md`(결정 26건), `docs/worklogs/`, `docs/PROJECT_STATE.md`. 이 글은 그 기록에서 뽑은 교훈 정리다.

## 1. 제품·도메인

**정답을 숨기는 것이 기능이다.** 이 앱의 핵심 가치는 "잘 풀어주는 것"이 아니라 "성급하게 답을 주지 않는 것"이다. 그래서 final-answer gate, 점진 힌트(hint level), trace-first disclosure가 전부 코드 레벨의 게이트로 존재하고, solution reveal은 런타임에서 아예 비활성으로 시작했다. 페다고지 정책을 프롬프트가 아니라 시스템 경계로 강제한 것 — 프롬프트는 어기지만 게이트는 못 어긴다.

**교육과정 전환기는 하나의 플래그로 못 다룬다.** 2026학년도엔 고1·2가 2022 개정, 고3이 2015 개정이다. "현재 교육과정" 전역 플래그나 학년→과목 추론 대신, 학년도+학년으로 적용 고시를 해석하고 학생의 실제 수강 과목은 별도 증거로 저장했다. 잘못된 과목 추론은 문제를 엉뚱한 개념·검증기로 보낸다.

**미성년자 대상 서비스는 법이 기술 선택을 지배한다.** Gemini Developer API는 18세 미만 대상 클라이언트를 약관으로 금지해서 기술 평가 자체를 제외했다. 성능·가격 비교 이전에 약관의 적격성부터 확인해야 한다. PDF·필기 원본은 transient 처리 자산으로 취급하고, 저장하는 모든 행에 승인된 목적과 삭제 트리거를 요구했다(PIPA).

## 2. AI 엔지니어링

**프로바이더는 서버 뒤에, 시크릿은 절대 클라이언트에 두지 않는다.** iPad 클라이언트는 provider-agnostic으로 유지하고, 서버 쪽 좁은 `AIProvider` 경계 하나만 뒀다. 프로바이더 선택은 잠긴 벤치마크와 법률·프라이버시 게이트를 통과한 뒤로 미뤘다. 기능 페이지의 벤치마크는 한국 고교 수학의 breakpoint 진단 성능을 증명하지 않는다 — 직접 측정 전엔 모른다.

**평가는 fail-closed로.** 시작 평가셋은 남의 문제은행을 긁는 대신 권리 메타데이터를 붙인 자작 fixture 16개로 만들고, 실행 가능한 oracle이 없는 검사는 전부 `specification-only`로 표시해 실패 처리했다. "통과한 것처럼 보이는 미검증"이 최악이다.

**테스트 픽스처와 실데이터의 경계는 코드로 강제해야 한다.** 이번 달 가장 아팠던 버그 계열: usage refresh가 deterministic fixture를 지워버리고, 반대로 로컬 ledger가 static fixture 값으로 수렴해버리는 오염. fixture→live 전환 시 시드된 상태를 명시적으로 drop하는 `configure()`를 만들고 나서야 잡혔다. 픽스처는 "편의"가 아니라 경계 관리가 필요한 상태다.

**자원 소모 전에 동의를 해소한다.** AI 처리 동의 확인이 질문 차감보다 늦으면, 거부한 학생의 질문이 사라진다. 순서를 reserve → 결과 표시 ACK → consume으로 바꾸고, 타임아웃 화면은 "차감되지 않았어요"까지만 말하게 했다(서버 예약 해제는 best-effort라 "해제됐다"고 주장하면 거짓이 될 수 있다). UI 문구 하나에도 시스템이 보증 못 하는 주장을 넣지 않는다.

## 3. 아키텍처

**규모에 정직한 설계.** 개발자 2명, 목표 동시 접속 300명 — 마이크로서비스와 Redis를 미리 깔 이유가 없다. modular monolith + 좁은 포트, PostgreSQL을 트랜잭션/outbox 경계로, 캐시는 측정 증거가 생기면. 대신 포트를 좁게 유지해서 나중에 어댑터만 갈아끼우면 되게 했다. "인터페이스 뒤에서 진화시키고, 미리 짓지 않는다."

**계약이 단일 진실이면 계약 위반은 컴파일 전에 잡히거나, 아니면 전면 장애다.** OpenAPI에 `additionalProperties: false`를 걸어둔 덕에, Swift가 follow-up intent를 `intent`로 보내고 계약은 `intent_code`를 요구하던 불일치가 "일부 이상 동작"이 아니라 "모든 실서버 요청 거부"로 명확히 드러났다. 엄격한 계약은 버그를 크고 일찍 터지게 만든다 — 그게 장점이다.

**스키마가 거짓을 거부하게 만든다.** 운영 마이그레이션에 account-owned 복합 FK, parent-bounded lifetime, monotonic queue evidence를 넣어서, 존재하지 않거나 남의 소유거나 만료됐거나 replay 충돌인 증거를 애플리케이션 검사가 아니라 데이터베이스가 거부하게 했다.

## 4. 프로세스·검증

**증거 계약: 보이는 것만 기록하고, 없는 건 undefined로 남긴다.** 디자인(Figma Make export)에서 관찰되는 동작만 UI 계약에 넣고, 익숙한 앱 패턴으로 빈칸을 채우는 것을 금지했다. 덕분에 "구현하다 보니 발명한 기능"이 없다. 디자인 일치는 느낌이 아니라 스크린샷 RMSE 수치(raw 0.1095, blur4 0.0358)로 기준선을 얼렸다.

**risk-gated vertical checkpoint.** 가장 작은 실행 가능한 수직 슬라이스 하나가 체크포인트 하나다. 슬라이스가 닫힐 때만 전체 회귀 + clean-context 적대 리뷰 + 상태 문서 갱신 + 커밋/푸시 1회. 중간 실패와 수정은 체크포인트 안에 머문다. 커밋마다 의식을 치르는 것도, 리뷰 없이 내달리는 것도 둘 다 피했다.

**UNVERIFIED를 정직하게 구분한다.** 시뮬레이터 검증이 환경 문제로 막혔을 때(샌드박스 훅이 쓰기를 차단), 2회 재시도 후 UNRESOLVED-ENVIRONMENT로 닫고 해당 항목을 전부 UNVERIFIED로 기록했다. static 리뷰 PASS와 런타임 검증 PASS를 절대 섞지 않는다. "검증했다"는 말은 도구 출력이 있을 때만 쓴다.

**결정은 양식으로 기록한다.** Decision / Options considered / Rationale / Cost / Risk / Rollback / Evidence — 이 양식으로 한 달간 26건이 쌓였다. 몇 주 뒤 "왜 이렇게 했더라"가 없어지고, 되돌리는 비용이 항상 계산돼 있다.

## 5. 협업 (2인 + AI 에이전트)

- main 직접 푸시 금지. 모든 작업은 작은 브랜치 + Draft PR로 올리고 상대 리뷰 후 병합.
- 남의(과거의 내) dirty checkout은 지우지 않는다. 로컬 구현이 지저분해도 커밋으로 복구점을 만든 뒤 진행했고, 쓰기는 별도 git worktree로 격리했다.
- 같은 체크아웃에서 두 AI 세션이 겹칠 수 있다. 매 라운드 시작마다 `git log`/`git status`로 드리프트 체크를 넣고 나서야 안전해졌다.
- 검증 위임: 빌드/테스트/스크린샷은 Codex에 위임하고 Claude는 자체 검증하지 않는 분업. 위임한 검증의 결과(토큰·소요시간 포함)도 워크로그에 남겼다.

## 6. 대표 버그 5선

| 버그 | 교훈 |
|---|---|
| 학습 캘린더가 매달 첫 며칠을 드랍 | 요일 경계 수식은 `(weekday-firstWeekday+7)%7`처럼 음수 모듈로까지 검증. 경계 fixture(2월 28/29, 12월→1월, 일/토 시작)를 테스트로 고정 |
| usage refresh가 테스트 fixture를 삭제 / ledger가 fixture로 수렴 | fixture와 실데이터는 명시적 전환 코드로 경계를 끊는다 |
| follow-up intent를 `intent`로 인코딩 (계약은 `intent_code`) | 인코더 테스트는 올바른 키의 존재만이 아니라 잘못된 키의 부재도 assert |
| 모든 403을 동의 거부로 분류 | 에러 분류는 상태코드가 아니라 code/messageKey 기준으로 |
| 계정 전환 후 이전 요청의 defer가 새 요청의 busy 플래그를 해제 | async defer에는 generation guard — 시작 시점 세대를 캡처하고 일치할 때만 정리 |

## 7. 한 줄 요약

기능보다 경계를 먼저 만들었다 — 페다고지 게이트, 프로바이더 포트, 계약 스키마, 증거 계약, 체크포인트 규칙. 경계가 있으면 AI 에이전트를 여럿 붙여도 프로젝트가 산으로 가지 않는다.
